# Datascene Analysis Report panel — workflow design

The Analysis Report is a first-class interpretation surface, not an export
preview and not a replacement for evidence panels.

## Dual reading regime

- **Fast scan** answers: what was analysed, what is confirmed, what remains a
  candidate, what is withheld, and where should attention go next?
- **Evidence review** answers: what source supports the account, which method or
  lens produced it, what maturity and uncertainty apply, and how can the analyst
  return to the operational panel?

Both modes read the same governed records. Fast scan may abbreviate; it may not
erase candidate/withheld distinctions or manufacture prose for missing data.

## Required report views

1. Summary text.
2. Scene-based summaries.
3. Narrative-structure viewpoints.
4. Narrative-agent summaries.
5. Statistical indicators and significance claims.
6. Quant and POS summaries.
7. Selected-lens summaries.
8. Analysis maturity graph.
9. Cross-analysis comparison matrix with explicit project-bound row selection.

## Datascene invariants

- Every report claim remains linked to its source and provenance.
- Every report section returns to the associated operational panel.
- Report reading never asks for a second confirmation of mature evidence.
- Missing analysis is shown as missing, not converted into zero or prose.
- Lens interpretations remain attributable and do not silently become facts.
- Comparison never crosses the active project's hermeneutic boundary.
- Maturity counts describe governed state; they are not quality scores.
- A frozen Analysis 1.0 edition remains immutable; later corrections create a
  later edition.
